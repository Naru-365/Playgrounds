# デモ設計: 第3章「会議後」画面録画シナリオ

- **本編での位置**: 10:58 – 13:50（約172秒）
- **デモのゴール**: 「議事録づくり30分が、確認5分になる」ことを見せる
- **使用ツール**: Microsoft Teams（会議後の要約 / インテリジェント会議レポート） + Microsoft 365 Copilot
- **録画本数**: 5本

> 第2章で収録した模擬会議の文字起こしをそのまま使う。
> 第2章と第3章のデモが同じ会議で繋がっていることが、本編の説得力になる。

---

## 0. 事前準備

- [ ] 第2章で収録した模擬会議が終了済みで、要約が生成されていること
- [ ] 会議の「欠席者」役のダミーユーザーを1名決めておく（ステップ4のメール宛先）
- [ ] 議事録を貼り付ける先（Teamsチャット / OneNote / Loop など）を1つ決めておく
- [ ] 録画設定は第1章・第2章と同一（1920x1080 / 30fps / カーソル表示ON / 通知オフ）

---

## 1. ステップ1: 会議の要約を出す（約25秒）

### 操作手順
1. 会議終了後のチャット / 会議レポートを開く
2. 自動生成された要約が既にあることを見せる（**人が何もしていないのに存在する**のがポイント）
3. 上から下へゆっくりスクロールする

### ナレーション
> 会議が終わった時点で、要約はもうできています。
> 何を話したかを思い出すのは、これで十分です。

### 編集メモ
- スクロールは等速でゆっくり。速いスクロールは内容が読めず逆効果
- 「自動生成」であることを字幕で明示

---

## 2. ステップ2: 議事録の形に整える（約40秒）

自動要約をそのまま使うのではなく、**自社のフォーマットに合わせる**ことを見せる。

### 入力プロンプト
```
この会議の内容を、社内の議事録フォーマットで整理してください。
見出しは次の順で固定してください。
1. 会議の目的
2. 決定事項
3. 保留・持ち越し
4. 次のアクション
5. 次回までに確認すること
各項目は簡潔な箇条書きにし、推測は書かず、会議で実際に話されたことだけを書いてください。
```

### 期待される出力
- 指定した5つの見出しどおりの議事録
- 推測が混ざっていない

### ナレーション
> コツは、見出しを指定することです。
> こう指定しておけば、「いつもの議事録の形」を毎回同じ品質で再現できます。
> 「推測は書かないで」の一言も効きます。

### 編集メモ
- プロンプトの「見出しは次の順で固定してください」の行にハイライト
- 出力の見出しとプロンプトの見出しが一致していることを、線で結ぶアノテーションで見せる

---

## 3. ステップ3: アクションアイテムを表にする（約42秒）

### 入力プロンプト
```
この会議で発生したアクションアイテムを表にしてください。
列は「タスク / 担当者 / 期限 / 根拠となった発言」の4列です。
担当者や期限が会議中に決まらなかったものは「未定」と書き、
勝手に補完しないでください。
```

### 期待される出力
- 4列の表
- 担当・期限が「未定」の行が1つ含まれる
- 「根拠となった発言」列があり、確認できる

### ナレーション
> ここが一番のポイントです。
> 「勝手に補完しないで」と書いておくと、決まっていないものは「未定」と返ってきます。
> そして「根拠となった発言」の列。ここを見れば、人が5秒で確認できます。
> 担当と期限は、必ず人の目で確認してください。ここだけは省略しないでください。

### 編集メモ
- 「未定」のセルを赤系でハイライト
- 「根拠となった発言」列に矢印アノテーション
- ナレーションの「必ず人の目で」に合わせて画面全体を一度引きにする（強調のため）

---

## 4. ステップ4: フォローアップメールを作る（約35秒）

### 操作手順
1. 続けて入力する
2. 生成されたメール文面を**実際にメールの下書きへ貼り付ける**ところまで見せる

### 入力プロンプト
```
今日の会議に欠席したメンバー向けに、共有メールの下書きを作ってください。
条件:
- 件名を付ける
- 冒頭3行で結論が分かるようにする
- 決定事項とアクションアイテムを箇条書きで入れる
- その人にお願いしたいことがあれば最後に明記する
- 敬体で、200〜300字程度
```

### 期待される出力
- 件名付きのメール文面
- 冒頭3行に結論
- 箇条書きの決定事項とToDo

### ナレーション
> 欠席した人への共有まで含めて、会議後の作業はここで終わりです。
> 送る前に読むのは人の仕事ですが、白紙から書く必要はもうありません。

### 編集メモ
- 下書きに貼り付けるカットを必ず入れる（「使えるところまで見せる」）
- 宛先はダミーであることを字幕で明示

---

## 5. ステップ5: 次回会議への引き継ぎ（約30秒）

**第1章の入口に戻る**、本編の締めにあたるステップ。

### 入力プロンプト
```
今日持ち越しになった論点をもとに、次回の定例（60分）のアジェンダ草案を作ってください。
持ち越し事項を最初に置き、各項目に想定時間と「共有／議論／決定」のラベルを付けてください。
```

### 期待される出力
- 次回アジェンダの草案（第1章ステップ4と同じ形式）

### ナレーション
> 持ち越した論点が、そのまま次回のアジェンダになりました。
> お気づきかもしれません。これは第1章でやったことと同じです。
> 会議後の整理が終わった時点で、次の会議前の準備も終わっている。これが一番効いてきます。

### 編集メモ
- 第1章ステップ4の出力画面を**画面右半分に小さく並べて表示**し、同じ形式であることを見せる
- ここでBGMを盛り上げ、クロージングへ繋ぐ

---

## 6. 収録チェックリスト

- [ ] 第2章と同じ会議のデータを使っている
- [ ] 実名・実データが映っていない
- [ ] 「未定」の行が実際に出ている（出ない場合はプロンプトを調整して再収録）
- [ ] メール下書きへの貼り付けまで見せている
- [ ] 各ステップの尺が目標±10秒

## 7. リスク対策

- 要約が事実と異なる部分を含む場合がある。その場合は**修正せずにそのまま見せ**、
  ナレーションで「だから人の確認が必要です」と繋ぐ選択肢もある（誠実さの担保として有効）
- ただし、誤りが大きすぎて誤解を招く場合は再収録する
